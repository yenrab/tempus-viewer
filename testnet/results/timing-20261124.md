## Caveats

- One machine, loopback: the round trip time is about 0.05 ms and the bandwidth is memory speed. The handshake's CPU cost (key exchange, signatures, certificate and token checks, on both sides) is what the table shows; the network's time is not.
- The client is Python (`ssl`, OpenSSL 3.6.2) and the nodes are Silica native programs with OpenSSL 4.x; a Swift viewer's client costs differ. Client and nodes share the same cores, so concurrent rows partly measure contention between the client's threads (Python's GIL covers the framing code, not OpenSSL) and the nodes.
- Whether X25519MLKEM768 was the group negotiated is not observable from Python's `ssl` (it reports no group); it is what the nodes' OpenSSL 4.x offers first, and the client's OpenSSL 3.6.2 is new enough to offer it, so it is expected, not proven here.
- The bridge runs BEES's test unit (fixed clock 1500) and the limits of `nodes/bridge/bridge.role.in` (`slim 5`, `size 4`, `rate 100000` per hour, `pin 2`, `tin 4`, `cms 4000`); refusals in section 3 show those, not production values.
- The nodes are the builds of `build.sh`; this trial did not compare debug and release builds of the nodes.
- A real network adds round trips, not CPU: see the README section 'Timing trial' for how many.

Total run time of the trial: 39 s.
